# Логика проверки цены относительно последней сделки

## Описание проблемы

Ранее бот открывал сделки по текущей рыночной цене без учета цены последней сделки по тому же направлению. Это могло приводить к убыточным входам, когда:

- При шорте цена была ниже последней сделки (убыточный вход)
- При лонге цена была выше последней сделки (убыточный вход)

**Дополнительная проблема:** Система не учитывала время сигнала при поиске последней сделки, что могло приводить к сравнению с сделками, которые произошли **после** времени сигнала.

**Проблема с типом позиции:** Система использовала кэшированное значение `current_positions[symbol]` для определения типа позиции, которое могло быть не синхронизировано с реальным состоянием позиций на бирже.

## Реализованное решение

### Новые функции

1. **`get_last_trade_info(symbol, signal_time=None)`** - получает информацию о последней сделке для символа (цена и направление)
2. **`get_current_position_type(symbol)`** - определяет тип текущей позиции из API (buy/sell/None)
3. **`should_open_position(symbol, signal_type, current_price, signal_time=None)`** - проверяет, можно ли открывать позицию

### Исправление фильтрации по времени

**Проблема:** Система могла сравнивать цену сигнала с сделками, которые произошли после времени сигнала.

**Решение:** Добавлен параметр `signal_time` в функции, который позволяет фильтровать сделки по времени:
- Ищутся только сделки, которые произошли **до** времени сигнала
- Это обеспечивает корректное сравнение цены сигнала с релевантными историческими сделками

### Исправление определения типа позиции

**Проблема:** Система использовала кэшированное значение для определения типа позиции, что могло приводить к неправильным сообщениям типа "Sell сигнал, позиция остается открытой" при LONG позиции.

**Решение:** Добавлена функция `get_current_position_type()`, которая:
- Получает реальный тип позиции напрямую из API
- Определяет тип позиции по полю `side` (Buy/Sell)
- Обеспечивает корректное сравнение сигнала с реальным состоянием позиции

### Логика работы

**Новая улучшенная логика:**

1. **Поиск последней сделки**: Ищется последняя сделка по символу (независимо от направления)
2. **Сравнение с учетом направления**:
   - **Если последняя сделка была SHORT и сигнал SHORT**: ждем цену **ВЫШЕ** последней сделки
   - **Если последняя сделка была LONG и сигнал LONG**: ждем цену **НИЖЕ** последней сделки
   - **Если направления разные**: можно открывать (разворот позиции)
3. **Фильтрация по времени**: Учитываются только сделки, которые произошли **до** времени сигнала

### Интеграция

Логика интегрирована в:
- `main.py` - основной торговый цикл
- `web_app.py` - веб-интерфейс торговли

### Примеры работы

**Пример 1: Последняя сделка SHORT (24.794)**

```
Сигнал SHORT, цена 22.444:
- ❌ Цена ниже последней SHORT сделки - ждем лучшего входа для шорта

Сигнал SHORT, цена 25.000:
- ✅ Цена выше последней SHORT сделки - можно открывать шорт

Сигнал LONG, цена 25.000:
- ✅ Разворот с SHORT на LONG - можно открывать лонг
```

**Пример 2: Последняя сделка LONG (23.81)**

```
Сигнал LONG, цена 22.000:
- ✅ Цена ниже последней LONG сделки - можно открывать лонг

Сигнал LONG, цена 25.000:
- ❌ Цена выше последней LONG сделки - ждем лучшего входа для лонга

Сигнал SHORT, цена 25.000:
- ✅ Разворот с LONG на SHORT - можно открывать шорт
```

### Пример исправления фильтрации по времени

**Ситуация:**
- Сигнал: 2025-09-04 16:45:00 - цена: 22.444 (Sell)
- Сделки в логе:
  - 2025-09-04 15:23:17 - LINKUSDT Sell 24.794 ✅ (до сигнала)
  - 2025-09-04 20:45:50 - LINKUSDT Buy 23.81 ❌ (после сигнала)

**Старая логика:** Могла сравнивать с любой последней сделкой
**Новая логика:** Сравнивает только с сделками до времени сигнала (15:23:17)

### Преимущества

1. **Предотвращение убыточных входов** - не открываем позиции в невыгодном направлении
2. **Улучшение качества входов** - ждем лучших цен для входа
3. **Гибкая логика сравнения** - учитывает направление последней сделки и сигнала
4. **Корректная фильтрация по времени** - учитываем только релевантные исторические сделки
5. **Точное определение типа позиции** - использует реальные данные из API
6. **Поддержка разворота позиций** - позволяет открывать противоположные позиции
7. **Совместимость** - работает с существующим кодом без breaking changes
